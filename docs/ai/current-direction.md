# DocklistAI Current Direction

Compact statement of what Docklist is building now. Keep this file short. Individual bugs and feature tickets belong in the backlog, not here.

## Mode

Product build / refinement. See the *Current mode* section of `docs/ai/DOCKLIST_OPERATING_SYSTEM.md`.

## Product shape

- **50% scheduling** — the product centre.
- **30% lightweight HR** — enough workforce admin to support scheduling, not an HR suite.
- **20% limited manager-led AI** — assistive and manager-approved, never autonomous.

## How we work

Real product workflow → browser observation / audit → product decision → substantial bounded implementation → self-correction of introduced defects → complete verification → exact staging → commit/push when explicitly authorised → external GitHub verification → next product batch.

## Next product focus

**Core weekly workflow integrity** — making the manager's week hold together end to end.

Current categories under that heading:

- department authority consistency;
- trustworthy import;
- Build on a genuinely fresh week;
- manager visibility for open-shift applications;
- scalable staff portal access-code onboarding;
- real manager contact in the portal;
- visible open-shift demand / coverage;
- addressable Settings;
- manager-side availability and day-off recording.

This list is **context, not authorisation**. Implement an item only when the owner scopes it as a batch.
